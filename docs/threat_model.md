# 위협모형 (Threat Model) — 외부 AI 사전 트리아지에서 무엇이 노출되는가

작성 목적: 이 저장소의 실험이 측정하는 "노출(exposure)"이 실제로 어떤 보호법익과
연결되는지를 명시한다. 기존 설계는 **시스템이 되돌려 주는 공개 통제목록 문자 수**를
노출량으로 정의했는데, 그 값은 기업의 미공개 기술정보 보호와 인과적으로 무관하다.
이 문서는 그 불일치를 명문화하고, 정정된 측정 대상(질의 측 노출)을 정의한다.

관련 산출물
- 질의 측 노출 등급 데이터: `data/disclosure_ladder.json` (생성: `build_disclosure_ladder.py`)
- disclosure–recall frontier 실험: `experiment_disclosure_frontier.py`
  → `output/disclosure_frontier.json`, `output/disclosure_frontier.md`

## 1. 시나리오

국내 수출기업의 무역·컴플라이언스 담당자가 자사 제품이 전략물자에 해당할 수 있는지
**사전 판단(트리아지)**을 받기 위해, 외부에서 제공되는 대화형 AI 또는 검색 서비스에
제품 설명을 입력한다. 서비스는 공개 통제목록(Wassenaar / eCFR Supplement No.1 to
Part 774 / SCOMET 등)에서 후보 항목을 찾아 되돌려 준다.

거래는 두 방향의 데이터 흐름으로 구성된다.

```
   사내망(신뢰)                    │  신뢰경계  │        외부 서비스(비신뢰)
   ────────────────────────────────┼───────────┼──────────────────────────────
   담당자가 작성한 제품 설명  ──────┼──▶ 아웃바운드 ──▶ 프롬프트/질의 로그, 학습 재사용
                                   │           │
   후보 통제항목 목록      ◀────────┼── 인바운드 ◀── 공개 통제목록 발췌
```

## 2. 보호자산 / 상대 / 경계 / 채널

| 구분 | 내용 |
|---|---|
| **보호자산 (protected asset)** | 기업의 **미공개** 기술·영업정보: ① 도면·설계 파라미터, ② 정량 사양치(치수·공차·주파수·출력·정밀도·온도·전압·분해능·재료 조성), ③ 공정 조건·제조 노하우, ④ 고객·최종사용자·목적지·납기 등 거래정보, ⑤ 미출시 제품·시제품의 존재 자체와 개발 단계 |
| **비자산 (non-asset)** | Wassenaar·eCFR·SCOMET 통제목록 문언. **전부 공개문서**이며 누구나 원문을 무료로 열람·다운로드할 수 있다. 이 텍스트를 덜 보여 주는 것은 어떤 기업 비밀도 보호하지 않는다. |
| **노출 상대 (adversary / disclosee)** | ① 외부 LLM·검색 서비스 운영자(및 그 하위 처리자), ② 모델 학습·미세조정 재사용, ③ 프롬프트 로그의 장기 보관과 내부 열람, ④ 제3국 관할권에 따른 정부 접근 요구, ⑤ 서비스 침해 시 로그 유출, ⑥ 동일 서비스를 쓰는 경쟁사에게의 간접 전이(모델 기억) |
| **신뢰경계 (trust boundary)** | 사내망/사내 시스템 ↔ 외부 API·웹 서비스. 경계를 넘는 순간 기업은 해당 데이터에 대한 기술적 통제권을 상실한다(삭제 요구권은 계약상 권리일 뿐, 이미 전송된 사실은 되돌릴 수 없다). |
| **노출 채널 ① 아웃바운드 = 질의 본문** | 담당자가 입력한 제품 설명. **보호자산이 실제로 신뢰경계를 넘는 유일한 지점.** 위험한 것: 정량 사양치, 제품·모델·공정 명칭, 최종사용자·목적지, 거래 형태(샘플/시제품/입찰), 자사 업종 정체성. |
| **노출 채널 ② 인바운드 = 반환 텍스트** | 서비스가 되돌려 준 통제목록 발췌. 위험한 것: **기업 비밀 관점에서는 없다.** 의미 있는 비용은 (a) 담당자의 읽는 시간, (b) 과도한 후보 제시로 인한 오해·오분류 유도, (c) 제3자 저작물 재배포 문제(SCOMET PDF 등 라이선스). 이는 사용성·법무 리스크이며 영업비밀 보호와는 다른 축이다. |

## 3. 기존 설계의 결함

기존 실험(`run_experiments.py`의 `exposure@10`, `experiment_exposure_frontier_validated.py`)은
노출량을 다음처럼 정의했다.

> 상위 10개 검색 결과로 **반환된 통제목록 텍스트의 문자 수 합**

이 정의의 문제는 세 가지다.

1. **보호법익 불일치.** 측정 대상이 채널 ②(인바운드, 공개문서)다. 논문의 동기 문장은
   "기업이 사양을 외부 AI로 **전송**하는 것이 위험하다"는 채널 ①의 주장인데, 측정은
   채널 ②에서 이루어졌다. 즉 동기와 지표가 서로 다른 채널을 가리켰다.
2. **자유 처분성.** 반환량은 검색 품질과 독립적으로 줄일 수 있다. 실제로
   (색인=`full_text`, 반환=`minimal_no_code`) 조건에서 노출량@10이 4043 → 1729
   (57.2% 감소)인데 **랭킹이 바뀌지 않으므로 R@10은 0.6056 그대로**다. 비용 없이
   줄일 수 있는 양을 "프라이버시-성능 트레이드오프"라 부를 수 없다.
   → 트레이드오프가 실제로 발생하는 곳은 **색인 축소**와 **질의 축소**뿐이다.
3. **문자 수라는 단위.** 문자 수는 민감도의 대리변수가 못 된다. "정밀도 ±0.5 µm"는
   11자이고 "본 장비는 산업용입니다"는 13자인데 민감도는 비교가 안 된다. 민감도는
   **필드 카테고리** 단위로 세어야 한다.

## 4. 정정된 측정 대상

노출은 **질의 본문에 남아 있는 민감 필드**로 측정한다. 문자 수가 아니라 사전 정의된
카테고리와 그 카테고리에 귀속된 토큰 수를 센다.

| 카테고리 | 정의 | 계수 대상 |
|---|---|---|
| `quantitative_spec` | 수치+단위, 정밀도·공차·성능 등급 표현 | ○ |
| `product_identifier` | 제품명·모델명·공정명·상표·특정 기술/재료 고유명칭 | ○ |
| `destination` | 목적지 국가·지역(불특정 '해외/foreign' 포함) | ○ |
| `end_user` | 수요기관의 유형·성격(대학·연구소·팹리스·방산업체 등) | ○ |
| `end_use` | 용도·응용 맥락(군용·미사일·잠수함·원자력·감시 등) | ○ |
| `supplier_identity` | 질의자 자신의 업종·사업자 정체성 | ○ |
| `transaction_intent` | 구체적 거래 형태·단계(샘플·시제품·입찰·견적·납품 예정) | ○ |
| `function` | 기능·물리적 원리(잔존 최소 정보) | × (잔존 서술) |
| `item_category` | 품목 대분류 키워드 | × (잔존 서술) |

`function`과 `item_category`를 계수에서 제외하는 근거: 2절의 보호자산 정의에서
"작동 원리 수준의 기능 서술"은 통상 공지 기술이고, 통제목록 자체가 기능 기준으로
쓰여 있으므로 이를 숨기면 트리아지 자체가 성립하지 않는다. 보호 대상은 그 기능을
**어느 수준으로 구현했는지(정량 사양)**와 **누구에게 보내는지(거래정보)**다.

## 5. 등급 사다리 (L0–L4)

| 등급 | 정의 | 아웃바운드로 넘어가는 것 |
|---|---|---|
| **L0** | 원문 그대로 | 전부 |
| **L1** | L0 − 정량 사양치(수치·단위·정밀도·공차·성능 등급) | 명칭·거래정보·용도 |
| **L2** | L1 − 고유명칭(제품·모델·공정·상표·특정 재료/기술명) + 규제 조문 인용 문구 | 거래정보·용도 |
| **L3** | L2 − 최종사용자·목적지·용도·자사 정체성·거래 형태 → 기능·원리만 | 기능 서술 |
| **L4** | 카테고리 키워드만(2~5 단어) | 품목 대분류 |

L2에서 규제 조문 인용 문구(예: "원자력 규제 대상은 아닌데", "falls outside standard
munitions lists")를 함께 제거하는 이유는 두 가지다. 첫째, 그것은 기업 정보가 아니라
**통제목록 원문에서 옮겨 적은 문언**이므로 자기참조(self-reference) 오염이다. 둘째,
그 문구가 남아 있으면 후보검색 성능이 질의 작성자의 사전 법률지식에 의존하게 되어
"정보를 덜 보내면 성능이 어떻게 되는가"라는 질문 자체가 오염된다.

## 6. 이 위협모형이 답하는 질문 / 답하지 못하는 질문

**답한다.** 정량 사양치를 지우면 후보검색이 유지되는가. 고유명칭까지 지우면?
최종사용자·목적지까지 지우면? — 어느 등급에서 후보검색이 무너지는지(굴절점)를 찾아
"외부 AI에 보내도 되는 최소정보 기준"의 실증 근거를 만든다.

**답하지 못한다.**
- 실제 LLM 서비스의 로그 보관·학습 재사용 여부(계약·정책 문제이며 이 저장소에서
  측정 불가). **확인 필요** 항목으로 남긴다.
- 질의 축소가 최종 **법적 판정** 정확도에 미치는 영향. 이 실험의 지표는 후보검색
  성능(R@10)이며 전략물자 해당/비해당 판정 정확도가 아니다.
- 재식별 위험: L3까지 축소해도 기능 서술만으로 특정 기업·제품이 추정될 수 있다.
  본 실험은 필드 제거만 측정하고 재식별 가능성은 측정하지 않는다. **확인 필요.**
- 반환 텍스트의 저작권·재배포 리스크는 별 트랙(M12)에서 다룬다.

## 7. 운용상 권고의 형태

frontier 실험이 산출하는 결론은 다음 형태의 문장이어야 한다.

> "L{k}까지 지운 질의로도 후보검색 성능이 L0과 사전지정 마진 δ=0.05 안에서
> 등가이므로, 외부 AI에 보낼 때 L{k} 수준까지는 지워도 된다. L{k+1}에서는
> R@10이 유의하게 하락하므로(Holm 보정 후) 그 이상 지우면 사내 도구가 필요하다."

이 문장의 δ와 검정 절차는 데이터를 보기 전에 고정한다(`experiment_disclosure_frontier.py`
상단의 사전지정 블록).
