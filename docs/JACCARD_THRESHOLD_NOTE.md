# 어휘 Jaccard 임계값 0.30은 어디서 왔는가

> 질문: "자기참조 게이트의 Jaccard 임계치를 0.3으로 잡은 이유가 뭔가?"
>
> **답: 유도 근거가 없다.** 초기 설정값이 그대로 굳은 것이다.
> 다만 이 임의성이 지금까지 어떤 수치도 바꾸지 않았다는 것은 확인했다.
> 심사에서 물어보면 방어하지 말고 아래 §4대로 답하는 편이 낫다.

---

## 1. 실제 유래

`validate_query_slice.py` 도입 커밋(`38415ce`)에서 이렇게 들어왔다.

```python
MAX_JACCARD = 0.30
MIN_QUERIES = 25
MIN_KO_RATIO = 0.40
```

`25`, `0.40`과 나란히 박힌 **어림수**다. 통계적 유도도, 대조군 보정도, 문헌 인용도
없다. 현재 `selfreference_gate.py`의 주석도 유래를 대지 못하고 이렇게만 적혀 있다.

```python
# 어휘 게이트는 원래 값을 유지한다(비교 가능성). 의미 게이트가 실질 게이트다.
MAX_JACCARD = 0.30
```

즉 **"처음에 정한 값이라 바꾸지 않았다"**가 전부다.

## 2. 대비되는 사례 — 의미 게이트 τ=0.44는 유도했다

같은 파일의 의미 게이트 임계값은 정반대 방식으로 만들어졌고, 그 대비가 이 문제를
더 눈에 띄게 만든다.

| | 어휘 게이트 | 의미 게이트 |
|---|---|---|
| 임계값 | 0.30 | 0.44 |
| 유래 | **없음(초기 설정값)** | POS-B 분포의 **10퍼센타일**을 소수 2자리 내림 |
| 대조군 | 없음 | POS-B: 정답 항목의 한국어 대역문 ↔ 영어 원문, n=57 (평균 0.5515, p10 0.4425) |
| 보조 대조군 | 없음 | POS-A 사람 번역쌍 n=5 (평균 0.8384) / NEG 무관쌍 n=3,020 (평균 0.1632) |
| 검증셋을 보고 정했나 | — | **아니오.** 151개 질의 분포와 독립인 대조군에서만 유도 |
| 민감도 | 없음 | 중앙값 컷(0.55)도 함께 보고 (초과 14건 → 2건) |
| 발동 | **0건** | 14건 |

10퍼센타일을 쓴 이유까지 코드에 적혀 있다 — 보수적이라 플래그가 덜 나오고, 따라서
"자기참조가 남아 있다"는 **연구자 주장에 불리한** 방향이기 때문이다.

**한쪽은 이렇게까지 설계해 놓고 다른 한쪽은 어림수**인 것이 현재 상태다.

## 3. 그런데 결과에는 영향이 없다 (설계가 아니라 운)

검증셋 n=151에서 관측된 어휘 Jaccard 최대값은 **0.2364**로 임계의 **78.8%**다.
그래서 이 게이트는 어느 언어에서도 **한 번도 발동하지 않았다.**

**임계값을 바꿨을 때 발동 건수**

| τ_lex | 발동 건수 |
|---:|---:|
| **0.30 (현재)** | **0** |
| 0.25 | 0 |
| 0.20 | 2 |
| 0.15 | 8 |
| 0.10 | 19 |
| 0.05 | 35 |

→ **0.24 이상 어떤 값을 쓰더라도 판정이 동일하다.**

**상위 5건** (전부 영어. 한국어는 최대 0.0385)

| 질의 | 언어 | Jaccard | LaBSE cos |
|---|---|---:|---:|
| g-seungwoo-023 | en | 0.2364 | 0.3484 |
| g-seungwoo-030 | en | 0.2105 | 0.4495 |
| j-seungwoo-036 | en | 0.1702 | 0.3746 |
| j-seungwoo-025 | en | 0.1556 | 0.3866 |
| g-seungwoo-026 | en | 0.1556 | 0.4942 |

한국어 109건 중 100건(91.7%)은 정확히 0이고 최대가 0.0385다. 코퍼스가 100% 영어라
한글 토큰은 원리상 교집합이 없기 때문이며, 0이 아닌 9건도 질의에 섞인 숫자·라틴
약어(`1`, `10`, `fadec`, `cvd`)에서만 나온 값이다.

즉 **임계값이 결과를 가르지 않은 것은 임계값을 잘 골라서가 아니라, 값이 임계 근처에
아예 오지 않았기 때문이다.** 데이터가 조금만 달랐으면 임의의 값이 판정을 갈랐다.

## 4. 심사에서 물으면 (그대로 써도 되는 문장)

> 어휘 게이트의 임계 0.30은 통계적으로 유도한 값이 아니라 슬라이스 검증기 도입 시의
> 초기 설정값이다. 다만 검증셋에서 관측된 어휘 Jaccard의 최대값이 0.2364로 임계의
> 79%에 그쳐 이 게이트는 어느 언어에서도 발동하지 않았으며, **0.24 이상 어떤 임계를
> 적용하더라도 판정 결과가 동일하다**(0.20에서 2건, 0.15에서 8건이 발동한다).
> 자기참조 통제의 실질적 부담은 의미 게이트가 지며, 그 임계 τ=0.44는 검증셋 질의와
> 독립인 대조군(정답 항목의 한국어 대역문 ↔ 영어 원문, n=57) 분포의 10퍼센타일에서
> 유도하고 중앙값 컷(0.55)에서의 민감도를 함께 보고하였다.

**요령**: 임계를 정당화하려 들지 말고 **무해함을 보이는 쪽**으로 답한다. 위 민감도 표를
논문에 넣으면 약점이 투명성으로 바뀐다. 지금 `docs/selfreference.md`에는 "임계의 79%"
라는 언급만 있고 **다른 임계에서 어떻게 되는지는 어디에도 없다.**

## 5. 하지 말아야 할 답변

- ❌ "0.30은 정보검색 분야의 관례적 임계값이다" — 근거 없다. 인용할 문헌이 없다.
- ❌ "예비 실험으로 정했다" — 그런 실험 기록이 저장소에 없다.
- ❌ 지금 와서 0.30을 사후 정당화하는 유도를 새로 만들기 — 데이터를 보고 임계를 정하는
  것은 이 연구가 τ=0.44 설명에서 명시적으로 피한 행위다. 같은 논문 안에서 한쪽은
  피하고 한쪽은 하면 그게 더 큰 문제가 된다.
